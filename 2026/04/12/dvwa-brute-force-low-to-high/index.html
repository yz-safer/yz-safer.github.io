【实战笔记】DVWA 暴力破解：从 Low 到 High 的通关指南

0. 前言

暴力破解（Brute Force）是针对身份验证最直接的攻击手段。通过遍历预定义的字典，尝试匹配正确的用户名和密码。在 DVWA 靶场中，我们将通过 Burp Suite 演示如何针对不同防御等级（从无防御到 Token 防御）进行破解测试。

1. 核心原理简述

暴力破解的本质是枚举。但在实际应用中，开发者会加入各种机制来提高破解成本：

  1. Low 级别：没有任何防御，直接根据返回包的长度或关键词判断结果。
  2. Medium 级别：加入了后端延时和失败限制，尝试增加攻击的时间成本。
  3. High 级别：引入了 Anti-CSRF Token，每次请求都需要携带上一次返回的唯一 Token，使得简单的自动化工具失效。

2. 实验环境与工具

  • 靶场：DVWA (Damn Vulnerable Web App)
  • 工具：Burp Suite Professional / Community Edition
  • 字典：常用的弱口令字典（如 top100_passwords.txt）

3. 靶场复现过程

3.1 Low 级别（无防御）

思路：直接爆破。

  1. 截包：在登录页面输入 admin/123，由 Burp Suite 拦截请求。
  2. 设置 Intruder：将 username 和 password 设置为攻击位置。
  3. 设置 Payload：使用 Cluster Bomb (集束炸弹) 模式，分别加载用户名和密码字典。
  4. 识别成功标志：观察返回包长度。正确的凭据通常会返回 HTTP 302 跳转或包含 “Welcome” 字样的页面，其长度与失败请求（显示 “Login failed”）明显不同。

3.2 Medium 级别（延时防御）

思路：源码中加入了 sleep(2)，失败后会暂停 2 秒。

  1. 现象：爆破速度明显变慢。
  2. 对策：在 Burp Intruder 的 Resource Pool 中调低并发线程数，保持耐心，或者寻找是否存在其他绕过方式。由于它只是简单的延时，爆破逻辑与 Low 级别完全一致。

3.3 High 级别（Anti-CSRF Token 防御）

思路：每个登录请求都包含一个隐藏字段 user_token，且该 Token 随页面刷新而改变。

  1. 核心挑战：简单的 Intruder 无法自动获取并填充动态 Token。
  2. Burp Suite 解决方案：
    • Macros (宏)：在 Settings -> Sessions 中配置宏，让 Burp 在每次请求前先访问登录页面抓取最新的 user_token。
    • Intruder 设置：
      • 攻击类型选择 Pitchfork。
      • 第一个 Payload 设为密码字典，第二个 Payload 设为 Recursive Grep（递归提取）。
      • 在 Options -> Grep - Extract 中找到响应包里的 user_token 并进行提取。
  3. 执行结果：Burp 会自动将上一次响应中的 Token 放入下一次请求，成功绕过防御实现爆破。

4. 防御建议与总结

暴力破解的有效防御手段：

  1. 多因素认证 (MFA)：即使密码被破获，没有验证码或生物识别也无法登录。
  2. 锁定策略：在连续尝试失败 N 次后，锁定账号或 IP 一段时间。
  3. 验证码 (CAPTCHA)：引入人机交互验证（如 Google reCAPTCHA），有效阻断全自动化工具。
  4. 强密码策略：要求密码包含大小写字母、数字及特殊符号，增加字典爆破的难度。
  5. Anti-CSRF Token：虽然 High 级别被我们绕过了，但在实战中，配合验证码的 Token 会让暴力破解变得极其艰难。

总结

从 Low 到 High 的过程，本质上是攻击成本与防御强度的博弈。作为渗透测试人员，我们需要掌握如何利用 Burp Suite 的高级功能（如 Macro 和 Recursive Grep）来处理动态参数。
