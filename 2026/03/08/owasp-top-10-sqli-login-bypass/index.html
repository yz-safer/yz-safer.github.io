【实战笔记】OWASP Top 10 - SQL 注入：身份验证绕过

0. 前言

在 Web 安全领域，SQL 注入（SQLi）始终高居 OWASP Top 10 榜单。本文记录了在 PortSwigger 学院中完成的“允许登录绕过的 SQL 注入”实验过程及底层原理分析。

注：以上标签以上的文字会显示在首页摘要，点击“阅读全文”才能看到后面内容。

1. 漏洞原理简述

SQL 注入 (SQL Injection) 是由于应用程序未对用户输入的 SQL 指令进行有效过滤，导致后端数据库执行了非预期的查询。

在登录绕过场景中，后端验证逻辑通常如下：
SELECT * FROM users WHERE username = 'USER_INPUT' AND password = 'PASSWORD_INPUT'

通过构造特殊的输入，我们可以破坏原有的逻辑结构，强制使查询结果返回“真”。

2. 核心 Payload 分析

本次实验针对 username 字段使用了以下注入语句：

Payload: administrator'--

逻辑解析：

  • ' (单引号)：闭合 SQL 语句中 username 值的左半部分。
  • -- (注释符)：在 SQL 中代表单行注释，它会使数据库忽略掉后面原本用于校验密码的 AND password = '...' 部分。

3. 靶场复现过程

实验环境：PortSwigger Academy - SQL injection vulnerability in WHERE clause allowing login bypass

复现步骤：

  1. 截获请求：打开实验页面，点击 Login。在提交表单时，通过 Burp Suite（或浏览器开发者工具）观察请求参数。

  2. 构造 Payload：在 username 字段输入 administrator'--，密码随机填写。

  3. 执行结果：点击 Log in 后，系统成功识别我为 administrator 用户，并跳转至管理页面。

4. 防御建议

最根本的解决办法是不要拼接 SQL 字符串。
