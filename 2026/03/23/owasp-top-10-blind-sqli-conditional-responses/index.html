【实战笔记】OWASP Top 10 - 基于条件响应的布尔盲注 (Boolean-Based Blind SQLi)

0. 前言

在之前的实验中，我们利用 UNION 直接将数据“回显”到了页面上。但在现实场景中，许多应用程序虽然存在注入漏洞，却不会在页面上显示任何查询结果。此时，我们需要通过观察应用程序在接收不同指令时返回的条件响应（如：是否显示特定欢迎词）来逐位“猜解”数据库内容。

1. 漏洞原理简述

布尔盲注（Boolean-Based Blind SQLi） 是一种通过使数据库执行逻辑判断，并根据页面响应的差异（真/假）来提取数据的方法。

核心逻辑：

  1. 构造判断题：向数据库提问，例如：“管理员密码的第一位是 ‘a’ 吗？”
  2. 观察响应：
    • 如果页面显示了预期的内容（如 “Welcome back!”），说明判断为真 (True)。
    • 如果页面内容发生变化或缺失，说明判断为假 (False)。
  3. 逐位爆破：利用这种二元状态，配合 SUBSTRING() 函数，我们可以猜解出完整的字符串。

2. 核心 Payload 与函数分析

关键 SQL 函数：

  • SUBSTRING(string, start, length)：截取字符串。SUBSTRING('password', 1, 1) 返回 ‘p’。
  • LENGTH(string)：返回字符串长度。

实验 Payload 结构：

' AND (SELECT SUBSTRING(password, 1, 1) FROM users WHERE username = 'administrator') = 'a'--

逻辑解析：

  • 如果管理员密码的第一位确实是 ‘a’，则 AND 后面的条件为真，整个查询返回结果，页面显示 “Welcome back!”。
  • 如果不是 ‘a’，条件为假，页面不显示 “Welcome back!”。

3. 靶场复现过程

实验环境：PortSwigger Academy - Blind SQL injection with conditional responses

复现步骤：

  1. 确认注入点：
    发现请求中包含 TrackingId Cookie。尝试修改：

    • TrackingId=xyz' AND '1'='1 -> 页面显示 “Welcome back!”
    • TrackingId=xyz' AND '1'='2 -> “Welcome back!” 消失。
      结论：存在布尔盲注漏洞。

  2. 探测密码长度：
    注入：' AND (SELECT LENGTH(password) FROM users WHERE username = 'administrator') > 19--
    通过递增数字，发现当长度为 20 时页面正常，21 时消失。确认密码长度为 20位。

  3. 逐位猜解密码 (自动化攻击)：
    由于手工猜解 20 位密码（每位需尝试 a-z, 0-9）效率太低，使用 Burp Intruder：

    • 位置：...SUBSTRING(password, §1§, 1) = '§a§'--
    • Payload 类型：Cluster Bomb (集束炸弹)。
    • 设置：第一个位置为 1-20 (Numbers)，第二个位置为 a-z, 0-9 (Simple list)。
    • 筛选：在 Intruder 的 Options 中设置 “Grep - Match”，添加 “Welcome back!”。

  4. 执行结果：
    根据 Intruder 筛选出的“真”值，按顺序拼接出 20 位字符串。
    使用 administrator 和该密码成功登录。

4. 防御建议与总结

关键点总结

  • 盲注的代价：盲注不需要回显，但需要大量的 HTTP 请求。实战中常配合二分法（Binary Search）或自动化脚本来提高效率。
  • 隐蔽性：这种漏洞在扫描器不开启深度探测时较难发现，但危害巨大。

防御方案

  • 参数化查询 (Prepared Statements)：无论是否盲注，预编译始终是终结 SQL 注入的最强防御。
  • 通用错误处理：确保无论数据库查询成功还是失败，页面返回的信息量尽可能一致，不给攻击者留下区分“真假”的机会。
  • 频率限制 (Rate Limiting)：盲注依赖大量请求，通过限制同一 IP 的请求频率可以有效减缓攻击。
