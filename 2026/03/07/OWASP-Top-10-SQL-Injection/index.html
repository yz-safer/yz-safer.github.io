【实战笔记】OWASP Top 10 - SQL注入基础原理与万能密码绕过

1. 什么是 SQL 注入？

简单来说，SQL 注入就像是你在填表格时，在原本应该填“姓名”的地方填入了一段“后台指令”。

当服务器没有对你输入的内容进行严格检查，直接把这段指令拼接到数据库查询语句中时，数据库就会“误以为”这是开发人员让它执行的操作。通过这种方式，攻击者可以越过权限，直接读取、修改甚至删除数据库里的敏感数据。

2. 核心 Payload 分析

在登录界面，最经典的“万能密码”通常是：
' OR 1=1--

为什么它能生效？

假设后台的 SQL 查询逻辑是：
$SELECT * FROM users WHERE username = ‘admin’ AND password = ‘$password’$

当我们输入上述 Payload 后，SQL 语句变成了：
$SELECT * FROM users WHERE username = ‘admin’ AND password = ‘’ OR 1=1 –’$

  • ' (单引号)：用来闭合掉代码中原本的第一个单引号。
  • OR 1=1：由于 $1=1$ 恒等于真（True），整个 WHERE 子句的结果永远为真。
  • -- (注释符号)：这非常关键。它会把后面剩下的 SQL 代码（比如原本用来验证密码的结尾引号）全部变成注释掉，让数据库直接忽略它们。

结果：数据库不看密码，直接让你登录成功！

4. 防御建议

想要彻底杜绝 SQL 注入，靠过滤特殊字符是不够的，最标准且有效的方案是：

  • 参数化查询（Parameterized Queries / Prepared Statements）：
    它的原理是在 SQL 语句发送到数据库之前，先定义好“模板”。无论用户输入什么（哪怕是删库指令），都会被数据库严格当成“普通的字符串”处理，而不会作为代码执行。
  • 最小权限原则：
    Web 应用连接数据库的账号不应拥有 SA 或 root 权限，只给它业务所需的最小读写权限。
