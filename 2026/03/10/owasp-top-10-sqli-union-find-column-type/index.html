【实战笔记】OWASP Top 10 - SQL 注入：利用 UNION 寻找包含文本的列

0. 前言

在确定了原始查询的列数后，下一步是找出哪些列可以用来提取数据。由于 UNION 注入要求数据类型必须兼容，我们通常需要寻找支持 字符串（String/Text） 类型的列，以便在后续步骤中显示数据库中的敏感信息。

1. 漏洞原理简述

在执行 UNION SELECT 时，每一列的数据类型必须与原始查询对应列的类型兼容。

如果原始查询的第一列是整数（Integer），而你试图在 UNION 中注入字符串，数据库会抛出数据类型不匹配的错误。因此，我们需要通过逐列替换测试的方法，找到那个能够正常渲染字符串的“出口”。

2. 核心探测手法与 Payload 分析

假设我们已经通过 ORDER BY 确定原始查询有 3 列，接下来我们要依次测试每一列是否支持字符型数据。

测试步骤：

  1. 测试第一列：' UNION SELECT 'abc', NULL, NULL--
  2. 测试第二列：' UNION SELECT NULL, 'abc', NULL--
  3. 测试第三列：' UNION SELECT NULL, NULL, 'abc'--

逻辑解析：

  • NULL 的妙用：由于 NULL 可以转换成任何类型，它在探测时不会触发类型错误。
  • 常量字符串 'abc'：我们尝试将其中一个 NULL 替换为已知的字符串。
  • 观察响应：
    • 如果页面返回 HTTP 500 或报错，说明该列不支持字符串类型。
    • 如果页面正常渲染，并在原本显示数据的位置出现了 'abc'，说明该列可以用来提取文本数据。

3. 靶场复现过程

实验环境：PortSwigger Academy - SQL injection UNION attack, finding a column containing text

复现步骤：

  1. 确定列数：
    使用 ' ORDER BY 3-- 正常，' ORDER BY 4-- 报错，确认共有 3 列。
  2. 寻找文本列：
    • 尝试第一列：' UNION SELECT 'CoUV8K', NULL, NULL-- -> 报错 500。
    • 尝试第二列：' UNION SELECT NULL, 'CoUV8K', NULL-- -> 成功！ 页面正常显示了该随机字符串。
    • 尝试第三列：' UNION SELECT NULL, NULL, 'CoUV8K'-- -> 报错 500。
  3. 执行结果：确认第二列为文本列。在本实验中，只要在指定列位置注入实验要求的随机字符串，即可通关。
