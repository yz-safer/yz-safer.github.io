【实战笔记】OWASP Top 10 - SQL 注入：MySQL 与 Microsoft SQL Server 指纹识别

0. 前言

在渗透测试中，识别目标数据库是 MySQL 还是 SQL Server 至关重要。虽然两者在许多基础语法上相似，但在获取系统版本信息和处理注释符时存在细微却致命的差异。本文记录了在 PortSwigger 靶场中针对这两类数据库进行版本探测的过程。

1. 漏洞原理简述

不同数据库通过不同的全局变量或内置函数来暴露其版本信息。

核心差异对比：

特性 MySQL Microsoft SQL Server (MSSQL)
版本查询函数 @@version 或 version() @@version
注释符 # 或 -- (注意杠杠后有空格) --
FROM 子句 可选（不需要虚拟表） 可选

2. 核心 Payload 分析

探测列数

两者均可使用递增索引排序：
' ORDER BY 2--

提取版本信息 (MSSQL)

Payload:
' UNION SELECT @@version, NULL--

提取版本信息 (MySQL)

Payload:
' UNION SELECT @@version, NULL#
或者：
' UNION SELECT version(), NULL-- (注意 -- 后面必须接一个空格，否则在 MySQL 中不生效)

逻辑解析：

  • @@version：这是 MSSQL 和 MySQL 通用的全局变量，用于返回服务器的详细版本字符串。
  • 注释符差异：
    • MSSQL 接受标准的 -- 注释。
    • MySQL 的 -- 必须配合空格使用（-- ），或者直接使用 #。在 URL 环境中，# 需要编码为 %23。

3. 靶场复现过程

实验环境：PortSwigger Academy - SQL injection attack, querying the database type and version on MySQL and Microsoft

复现步骤：

  1. 确定列数：
    在 URL 参数中注入 ' ORDER BY 2%23 (使用 MySQL 的 # 编码)。
    页面响应正常；尝试 ' ORDER BY 3%23 报错。确认为 2 列。

  2. 寻找文本列：
    输入 ' UNION SELECT 'abc', 'def'%23。
    观察发现两列均可渲染字符串。

  3. 获取版本信息：
    由于不确定是哪种数据库，先尝试通用的 @@version：
    category=Gifts' UNION SELECT @@version, NULL%23

  4. 执行结果：
    页面输出了详细的版本信息，从而判定目标为 MySQL 数据库，实验成功。

4. 防御建议与总结

关键点总结

  • 空格陷阱：在针对 MySQL 进行注入时，如果使用 -- 而不加空格（或 URL 编码的 %20），会导致语法错误。这是实战中极易忽略的细节。
  • 联合测试：如果 ' UNION SELECT NULL-- 报错而 ' UNION SELECT NULL# 成功，可以立刻判定后端为 MySQL。

防御方案

  • 预编译语句（Prepared Statements）：强制将所有用户输入作为参数处理，使 @@version 等敏感变量无法被注入执行。
  • 最小化数据库报错：配置 Web 服务器仅返回通用错误页面（如 500 页面），不回显底层 SQL 语法错误。
  • 输入清理：对输入参数进行严格的类型检查（如 category 应只允许预定义的字符串）。
